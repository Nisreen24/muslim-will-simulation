Dev notes — what exists vs. what this adds:
• Confirmed by the product itself — the admin's Public Registration Packages page already marks the Family Plan row as locked with: “Family package — needs the member-count step”. This preview IS that missing step, applied to the admin assignment popup.
• Branch feature/vault-add-package (from Patriva) already has the admin path: Clients/GetAssignablePackages + Clients/AssignPackageManually, opened from the Bypass Plan Choice Screen toggle on Edit Client Header. It links the package, records a Completed manual PaymentStrip, and sets the bypass flag.
• Addition 1: when the selected package has packageType == "family", show the seat-count step (min 2, default 2).
• Addition 2: in AssignPackageManually, after assigning a family package call _familyService.EnsureFamilyForOwnerAsync(clientId, seats, packageId) — exactly what the purchase flow does (PricingController.ProcessCheckout, family branch). Without it no FamilyPlan row exists and the client cannot invite anyone.
• Production note: the currently deployed build has none of this admin path — the answer to “can we do this from the current system?” is no; it ships with this branch.
